# Ключевые определения и пункты — все 8 лаб

Термины даны в формулировках лекций, с номерами слайдов.

---

## Лаба 1 — Текстурирование (лекция 02)

- **Texture mapping** — техника задания вариаций свойств отражения поверхности объекта. Отражательная способность хранится в виде изображения и «сопоставляется» (map) с поверхностью (сл. 2).
- **Texture map** — само сохранённое изображение. Хранит не только цвет: непрозрачность, рассеянное освещение, нормали, смещение (сл. 3).
- **Формат текстуры** — определяет размер одного текселя, как интерпретировать данные и как они лежат в памяти (сл. 5).
- **Swizzling** — хранение текселей блоками, а не линейно. При фильтрации 2×2 линейная раскладка заставляет прыгать по памяти; блочная — нет. «Ротационно инвариантная локальность соседних текселей» (сл. 6).
- **UV-координаты** — задаются на вершину, определяют, какую часть текстуры сэмплировать. U — абсцисса, V — ордината, W — аппликата (сл. 7).
- **Mipmapping** (Multum In Parvo, «многое в малом») — цепочка изображений, каждое следующее вдвое меньше. Уровень 0 — самое большое, последний — log2(N), где N — длинная сторона (сл. 9).
- **BC1–BC7** — форматы блочного сжатия, которые GPU распаковывает аппаратно. BC1 — 3 канала + 1-битная альфа, BC3 — + 8-битная альфа, BC4 — один канал, BC5 — два, BC6 — HDR, BC7 — качественный RGBA (сл. 14).
- **Фильтрация**: Point (ближайший тексель), Linear (билинейное смешение), Anisotropic (для поверхностей под углом к зрителю) (сл. 25–26).
- **Minification** — один тексель меньше пикселя экрана; **Magnification** — тексель больше пикселя; фильтрация применяется и **между мип-уровнями** (сл. 28–30).
- **Режимы адресации** для координат вне [0,1]: Wrap (отбросить целую часть), Mirror (отражение на каждой целой границе), Clamp (зажать), Border (цвет границы), Mirror once (сл. 31–36).
- **Статические сэмплеры** — механизм задать массив сэмплеров прямо в root signature, без кучи типа SAMPLER. Максимум 2032 (сл. 41).

**Ключевые пункты:** DDS — формат «для работы с графикой», умеет мипы, блочное сжатие, массивы, кубмапы (сл. 12–13). Мип выбирается аппаратно по производным UV, `ddx`/`ddy` (сл. 43).

## Лаба 2 — Отложенный рендеринг (лекция 03)

- **Forward rendering** — затенение за один проход. Стоимость растёт как объекты × источники; лишняя работа на пикселях, которые потом перекроются (сл. 4–6).
- **Deferred rendering** — три этапа: opaque geometry stage, lighting stage, transparent geometry stage (сл. 8).
- **Opaque geometry stage** — растеризация **без освещения**: свойства поверхности пишутся в Geometric Buffer (сл. 9).
- **G-Buffer** — набор render target'ов со свойствами поверхности. Канонический пример — раскладка Killzone 2 (сл. 10).
- **Light stage** — запись глубины отключена, рисуется геометрия источника света, результат накапливается **аддитивным смешиванием** (сл. 11).
- **Transparent stage** — сортировка back-to-front, запись в буфер глубины отключена (сл. 12).
- **Light accumulation** — ambient добавляется **только один раз**, а не на каждый источник (сл. 13).
- **Full screen-aligned quad** и его замена **одним треугольником** — генерируются из `SV_VertexID`, без вершинного буфера (сл. 22–23).
- **Depth bound test** — отсечение по глубине при рисовании световых объёмов: cull front/back faces плюс функции глубины (сл. 24).
- **Blend equation**: `Final Color = (Source Color × SrcBlend) BlendOp (Dest Color × DestBlend)` (сл. 36).
- **Forward+** — три этапа: light culling, opaque pass, transparent pass. Свет отбирается по тайлам экранного пространства (сл. 27–28).
- **Tile-Based Deferred Shading** — G-буфер читается один раз на тайл, накладные расходы амортизируются (сл. 30).

**Ключевые пункты:** минусы deferred — сложность прозрачности и MSAA, расход памяти (сл. 14). Мировые координаты в G-Buffer избыточны: восстанавливаются из экранных координат и глубины (сл. 17). G-Buffer читается через `Texture2D.Load(int3)` (сл. 20).

## Лаба 3 — Тесселяция и карты нормалей (лекция 04)

- **Bump mapping** — семейство методов добавления мелких деталей без дополнительной геометрии (сл. 2).
- **Три подхода**: offset vector bump map, heightfield, normal map. Нормали хранятся в world / object / tangent space (сл. 3).
- **Упаковка нормалей**: `packed = (normal + 1) * 0.5`, распаковка `normal = normalize(packed * 2 - 1)` (сл. 4).
- **Tangent-space basis (TBN)** — матрица из касательной, бинормали и нормали; семантики TANGENT, BINORMAL, NORMAL (сл. 5).
- **Вывод T и B** — из рёбер треугольника и разностей UV, `f = 1/(du1·dv2 − du2·dv1)` (сл. 9).
- **Процесс Грама-Шмидта**: `T = normalize(T − dot(T,N)·N)`, `B = cross(N,T)` (сл. 11).
- **Parallax mapping** — смещение UV по высоте и вектору обзора. Развитие: offset limiting, steep parallax, parallax occlusion, relief (бинарный поиск) (сл. 12–18).
- **Hull shader** — две фазы: фаза контрольных точек и константная функция патча, выдающая `SV_TessFactor` и `SV_InsideTessFactor` (сл. 25, 32–33).
- **Tessellator** — фиксированная стадия, генерирует новые вершины по коэффициентам (сл. 26).
- **Domain shader** — получает барицентрические координаты (`SV_DomainLocation`), интерполирует и смещает вершину по карте высот (сл. 27, 34–35).
- **Distance adaptive tessellation**: `TF = (1 − t)·maxTF + t`, где `t = distance / maxTessellationDistance` (сл. 54).
- **Back-face culling в hull shader** — патч не рисуется, если все коэффициенты тесселяции равны нулю; условие `dot(vView, vFaceNormal) < −0.25` с эпсилоном против popping (сл. 69–70).

**Ключевые пункты:** зачем тесселяция — компактное представление, LOD, силуэты, анимация на низком разрешении (сл. 22). «Плохая причина» — ненужная тесселяция; в UE 5.0 её убрали в пользу Nanite (сл. 23). Pass-through hull shader — распознаваемый драйвером шаблон (сл. 38). Треугольники не должны быть мельче 8 пикселей (сл. 53).

## Лаба 4 — Оптимизация (лекция 05)

- **Три проблемы**: много draw call'ов и примитивов; объекты вне поля видимости; избыточная детализация (сл. 2).
- **Batching** — группировка объектов в один вызов отрисовки (сл. 3–4).
- **Instancing** — «дешёвые копии»: одна геометрия, много экземпляров (сл. 5–6).
- **LOD** — уровни детализации (сл. 7).
- **Frustum culling** — отсечение по пирамиде видимости (сл. 8–10).
- **Occlusion culling** — отсечение перекрытого (сл. 11–12).
- **Billboards / Impostors** — замена геометрии плоскостью с текстурой (сл. 13–14).
- **Z-Prepass** — предварительный проход только глубины, чтобы дорогой пиксельный шейдер не считался на перекрытых пикселях (сл. 15–17).
- **Command lists** — цель 15–30 списков на кадр, 5–10 вызовов `ExecuteCommandLists`; список должен занимать GPU не менее 200 мкс, желательно 500 (сл. 22–23).
- **Bundles** — наследуют состояние; NVIDIA рекомендует при 5+ повторах (сл. 25).
- **Multi-Engine** — три очереди: 3D, Compute, Copy (сл. 26).
- **Compute Queue** — до 10% выигрыша, аналогия с hyperthreading (сл. 27).
- **Root Signature Tables** — использовать `DENY_*_SHADER_ROOT_ACCESS`; проверки границ нет (сл. 34).

**Ключевые пункты:** PSO — драйвер не создаёт потоки для компиляции сам, похожие PSO компилировать в одном потоке (сл. 32–33). В DX12 многопоточность — забота приложения, а не драйвера (сл. 21).

## Лаба 5 — Тени (лекция 06)

- **Hard / Soft shadows** — жёсткие и мягкие тени (сл. 3).
- **Umbra / penumbra** — полная тень и полутень (сл. 34).
- **Shadow volumes** — геометрический подход: рёбра силуэта, выдавливание, «колпачки», подсчёт через буфер трафарета. Depth pass / depth fail (сл. 5–10).
- **Shadow maps** — сравнение глубины пикселя с глубиной из карты, отрисованной из позиции света (сл. 11).
- **Построение карты**: точечный источник — перспектива и шесть «камер», направленный — ортогональная проекция. Пиксельный шейдер можно установить в null (сл. 13–14).
- **Depth bias**: `Bias = DepthBias × r + SlopeScaledDepthBias × MaxDepthSlope`. `DepthBiasClamp` ограничивает смещение на полигонах под острым углом; смещение применяется **после** отсечения (сл. 18–20).
- **CSM, алгоритм**: разбить фрустум камеры на части, построить ортопроекцию под каждую, отрисовать карты, подключить в пиксельный шейдер (сл. 24).
- **Координаты фрустума в мире** — вершины NDC-куба переводятся обратным преобразованием (сл. 26).
- **Выбор каскада** — по глубине в **пространстве камеры**; камера смотрит в −Z, берётся абсолютное значение (сл. 31).
- **Texture2DArray** — тип для хранения массива карт глубины (сл. 32).
- **PCF (Percentage Closer Filtering)** — усредняются результаты сравнений, а не глубины (сл. 39).
- **Comparison sampler**: `float Object.SampleCmp(SamplerComparisonState S, float Location, float CompareValue, [int Offset])` (сл. 40).
- **Ambient occlusion** — глобальный метод затенения в противовес локальному Фонгу; **SSAO** — экранное пространство, впервые в Crysis, ядро со случайным вращением, ~16 выборок на пиксель и размытие по Гауссу (сл. 42–45). **HBAO**, **VXAO** — развитие (сл. 47–48).

**Ключевые пункты:** проблемы теневых карт — выбор bias, артефакты по краям, малые углы обзора (сл. 38). Viewport должен быть размером с карту, а не с окно (сл. 30).

## Лаба 6 — Система частиц (лекция 07)

- **Particle** — точка в трёхмерном пространстве. Другие формы: линии, полигоны, metaballs, 3D-модели (сл. 4).
- **Физика частицы**: силы дают ускорение, ускорение меняет скорость, скорость меняет положение (сл. 4).
- **Система частиц** — совокупность элементов, действующих автономно, но имеющих общие атрибуты. Динамична и **не детерминирована** (сл. 4).
- **Предположения Ривза**: частицы не сталкиваются друг с другом; не отбрасывают тень друг на друга, только на окружение; не отражают свет, моделируются как точечные источники (сл. 5).
- **Три стадии работы**: эмиссия, движение, рендеринг (сл. 6).
- **Методы эмиссии**: на кадр (`new = average + rand()·variance`) и на площадь экрана (сл. 7).
- **Интегрирование**: без сохранения состояния (аналитическое) либо итеративное — Эйлер, Стёрмера-Верле, Рунге-Кутта (сл. 8).
- **Жизненный цикл**: Generation (случайные начальные атрибуты), Dynamics (атрибуты — функции времени и других атрибутов), Death (возраст превысил время жизни, выход за границы, удар о землю, порог атрибута) (сл. 19).
- **Атрибуты частицы**: position, velocity, life span, size, weight, representation, color, owner. **Атрибуты системы**: particle list, position, emission rate, forces, current state, blending (сл. 13).
- **Rasterization**: количество живых частиц известно только GPU → **Indirect API**. `DrawInstancedIndirect`, топология POINTLIST без VB, IB и IA, `VertexId` = индекс частицы, геометрический шейдер разворачивает точку в четыре вершины билборда (сл. 18).
- **Bitonic sort** — хорошо распараллеливаемая сортировка на GPU для корректного альфа-смешивания (сл. 45–52).
- **Compute shader**: максимум 1024 потока на группу, `groupshared` до 32 КБ, синхронизация через `GroupMemoryBarrierWithGroupSync` (сл. 54, 57).
- **Tiled rendering частиц** — по мотивам Forward+: группы 32×32, отбраковка, сортировка и затенение по тайлам (сл. 58–69).
- **Soft particles** — спрайты плоские, а Z-буфер даёт результат «всё или ничего»; частица плавно растворяется у пересечения с геометрией (сл. 75–76).
- **Depth buffer collisions** — столкновения по буферу глубины: спроецировать частицу в экранное пространство, сравнить глубины, нормаль взять из G-буфера или через `ddx`/`ddy` (сл. 73).

**Ключевая мысль лекции:** «Если множество маленьких точек делают что-то одно и то же, наш мозг будет видеть то, что они делают, а не точки, которые это делают» (сл. 2).

## Лаба 7 — Гамма и пост-эффекты (лекции 08.1, 08.2)

**Гамма (08.1)**

- **Гамма** — экспоненциальная кривая отклика ЭЛТ-монитора: напряжение → интенсивность света (сл. 2–4).
- **Гамма-коррекция** — кодирование перед выводом и декодирование перед работой со значениями (сл. 31).
- **Почему не хранить линейно** — глаз лучше воспринимает оттенки чёрного, гамма 2.2 отдаёт им больше кодов; это схема сжатия (сл. 22–25).
- **sRGB** — стандарт HP и Microsoft, 1996; обязателен с DirectX 10 (сл. 26–27).
- **_SRGB-форматы в DirectX** — аппаратура декодирует при чтении через SRV и кодирует при записи через RTV (сл. 32).
- **Двойная гамма** — признаки: мелкие текстуры и мип-мапы темнее, чем должны, сдвиг цветовых тонов (сл. 33–34).
- **Правила**: текстуры цвета грузить как sRGB; **не применять** к картам нормалей, освещения и смещения; sRGB для финального RTV; **не использовать** для промежуточных RTV (сл. 41–44).
- **Color banding** — полосы. Пример: `255 · (1/255)^(1/2.2) = 21`, значения 1…20 не используются вообще (сл. 51).
- **Dithering** — маскировка полос шумом; матрица Байера; Void-and-cluster и синий шум как более качественные маски (сл. 54–60).
- **Screen-Door Transparency** — прозрачность через `clip(alpha − thresholdMatrix[x%4][y%4])` (сл. 62).

**Постобработка (08.2)**

- **LDR / HDR** — форматы `xxx_UNORM` с диапазоном 0…1 против `xxx_FLOAT`; **saturation** — обрезание всего выше единицы (сл. 4–5).
- **Tone mapping**: Рейнхард `ldr = hdr / (hdr + 1)` (сл. 6); экспозиционный `1 − exp(−hdr · Exposure)` (сл. 7).
- **Eye adaptation** — средняя яркость через мипы или compute-редукцию, `LuminanceFactor = (0.299, 0.587, 0.114)`, плавный переход между кадрами (сл. 9–11).
- **Bloom** — утечка света от ярких пикселей к тёмным. Bright pass по порогу яркости, затем размытие (сл. 13–15).
- **Gaussian blur** — **разделимое** ядро: два одномерных прохода вместо одного двумерного (сл. 18).
- **Vignetting** — затемнение по расстоянию до центра экрана (сл. 29).
- **Chromatic aberration** — каналы R, G, B читаются с разного расстояния от центра (сл. 31).
- **Color correction** — цветовой куб-LUT, применяется **после** тонального отображения (сл. 33).
- **Depth of Field** — плоскость фокусировки, **Circle of Confusion (COC)**; методы: Poisson disc blur, multi-passed diffusion, separable diffusion, summed-area table (сл. 36–38).
- **Screen Space Reflections** — марширование луча по пикселям (сл. 44).
- **God rays** — объёмное рассеяние света как пост-процесс: проход рассеяния и проход лучей (сл. 48–52).

## Лаба 8 — PBR (лекция 09)

- **Три условия PBR**: основана на модели микрофасеточной поверхности; соблюдает принцип сохранения энергии; использует физически обоснованную BRDF (сл. 3).
- **Микрофасеты** — любая поверхность в микроскопическом масштабе описывается крошечными идеально отражающими зеркалами. Более шероховатая поверхность — более хаотичный их набор (сл. 4).
- **Roughness** — аппроксимация: микрофасеты меньше пикселя, поэтому вводится один параметр, по которому считается, сколько их сонаправлено вектору **h** (сл. 5).
- **Сохранение энергии** — исходящая энергия не больше входящей. Отсюда: у шероховатой поверхности блик менее интенсивен (сл. 6).
- **Отражённая и преломлённая части**: отражённая не проникает внутрь материала, преломлённая поглощается и рассеивается (сл. 7).
- **Металлы** — вся преломлённая часть поглощается, **диффузного цвета у металлов нет** (сл. 9).
- **kS и kD**: `kD = 1.0 − kS`, сумма не превышает 1.0 (сл. 10).
- **Энергетическая яркость (radiance) L** — состоит из потока излучения, телесного угла и интенсивности излучения (сл. 11–15).
- **Телесный угол** — размер фигуры, спроецированной на единичную сферу (сл. 13).
- **Уравнение отражения** — интеграл по полусфере раскладывается в сумму по всем источникам света (сл. 17).
- **BRDF** — двунаправленная функция распределения отражений; аппроксимирует вклад каждого луча в отражённый свет с учётом свойств материала. Почти все системы реального времени используют **BRDF Кука-Торранса** (сл. 19).
- **Три множителя зеркальной части**: **D** — normal distribution function, сколько микрофасетов перпендикулярно halfway-вектору; **F** — уравнение Френеля, сколько света отражено под разными углами; **G** — geometry function, самозатенение материала (сл. 22).
- **Trowbridge-Reitz GGX** — NDF, где α — шероховатость; Дисней ввёл репараметризацию **α = Roughness²** (сл. 23).
- **Schlick-GGX + метод Смита** — учитывает и геометрическое препятствие (обзор), и геометрическое затенение (свет). Разные формулы `k` для луча света и для cubemap/IBL (сл. 25–26).
- **Френель-Шлик** — процент отражённого света в зависимости от угла обзора; на скользящих углах отражают все поверхности (сл. 28–29).
- **F0** — базовая отражательная способность при взгляде прямо. У диэлектриков не превышает 0.17, чаще ниже 0.08; у металлов 0.5…1.0 и **имеет цветовой оттенок**, поэтому задаётся триплетом RGB (сл. 32, 34).
- **Metallic workflow** — дополнительный параметр «металличность»; предвычислив F0 для обоих типов, можно использовать одно приближение Френеля. **0.04 подходит большинству диэлектриков** (сл. 33).
- **Итоговое уравнение** — параметр F по сути и есть коэффициент kS, то есть зеркальная часть BRDF содержит его **неявно** (сл. 35).
- **Shader lifehack** — вместо ветвления создавать одно-тексельную текстуру с нужным значением (сл. 37).
- **IBL (Image Based Lighting)** — освещать объекты не аналитическим светом, а рассматривать окружение как один большой источник (сл. 39).
- **Два требования IBL**: получить освещённость по любому направлению и решить интеграл в реальном времени (сл. 40).
- **Cubemap** — решение первого требования; панорама переводится в кубическую текстуру через геометрический шейдер и `SV_RenderTargetArrayIndex` (сл. 41–45).
- **Irradiance map (карта облучённости)** — предвычисленная свёртка диффузной части интеграла; заменяет константу ambient (сл. 48–53).
- **fresnelSchlickRoughness** — у окружающего света нет halfway-вектора, поэтому подставляется нормаль; нужна поправка на шероховатость, иначе эффект переоценивается (сл. 54–55).
- **Split-sum (Epic Games)** — зеркальный интеграл делится на две предвычислимые части (сл. 57).
- **Pre-filtered environment map** — как irradiance map, но для разных значений roughness, каждый уровень в свой мип (сл. 58–59). Упрощение: `N = R = V` (сл. 60).
- **Specular lobe** — форма рассеивания вокруг отражённого вектора, зависит от roughness (сл. 61).
- **Монте-Карло, квази-Монте-Карло, importance sampling** — последовательности с низким расхождением (**Hammersley**) и генерация векторов в сторону specular lobe (сл. 62–66).
- **BRDF integration map** — вторая часть интеграла, таблица по `n·ωi` и roughness; F0 вынесена за знак интеграла (сл. 69–77).

**Ключевой пункт:** PBR лучше Фонга тем, что материалы выглядят правдоподобно **вне зависимости от условий освещения** (сл. 2).
